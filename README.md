# Свой Qwen 27B для роя из 10 агентов с контекстом 250K+

> **Исходная задача** (как была поставлена):
> смотри мне нужно запустить ии локально но я в этом не разибраюсь помоги мне с этим разобраться моя задача
> использоваться 27B qwen с роем агентов к примеру 10 паралельным с какими нибудь достаточно большими
> контекстами 250К+ и желательно иметь как можно большую скорость но в тоже время я хочу это сделать
> максимальнь эффективно с точки зрения расходов но не жертвовать временем анализ помоги мне в этом
> разобраться детально

Всё ниже собрано и посчитано на **25 сентября 2026**. Цены и версии меняются быстро: перед покупкой перепроверьте.

## Короткий ответ

| Вопрос | Ответ |
|---|---|
| **Какая модель** | **Qwen3.8-27B** (14.08.2026, Apache 2.0), официальная версия **FP8** (`Qwen/Qwen3.8-27B-FP8`). Qwen 4 27B пока только анонсирована, ждать не стоит |
| **Почему задача решаемая** | Модель гибридная: KV-кэш есть только у 16 из 64 слоёв. 10 агентов × 256K = **~85 ГиБ** KV-кэша (у обычной 32B-модели было бы ~320 ГиБ) |
| **Чем запускать** | **vLLM 0.30** с FP8 KV-кэшем, кэшем префиксов, MTP и текстовым режимом. Готовая команда: `scripts/serve_vllm.sh` |
| **Какое железо** | Нужно ~130 ГиБ памяти GPU: **1× H200**, **1× B200** или **2× RTX PRO 6000**. RTX 5090, DGX Spark, Mac, мини-ПК для 10 × 250K не подходят |
| **Какая скорость** | Оценка при 10 агентах: ~60 ток/с на агента на H200, ~100 на B200, ~46 на 2× RTX PRO 6000. Повторный ход агента с кэшем — секунды, холодный старт 256K — 20–50 с |
| **Арендовать или купить** | **Арендовать.** При хорошей загрузке это ~$2 за 1 млн сгенерированных токенов против $8–14 в API с кэшем. Покупка 2× RTX PRO 6000 (~$42–52K) окупается за ~1.5–2 года только при работе 24/7 |
| **Главный рычаг скорости и экономии** | Кэш префиксов: общий контекст — в начало промпта, прогрев перед стартом, одинаковые настройки размышлений и инструментов у всех агентов |

## План действий

1. **Без GPU (бесплатно):** проверить скрипты на мок-сервере — [docs/04-zapusk.md, шаг 4.0](docs/04-zapusk.md).
2. **Качество (~$5):** прогнать свои задачи через API Qwen3.8-27B (OpenRouter/DeepInfra) и убедиться, что модель подходит.
3. **Пилот (~$10–20):** арендовать 1× H200 на 2–3 часа, запустить `./scripts/serve_vllm.sh h200`,
   проверить лог (ёмкость KV-кэша), прогнать `scripts/bench_swarm.py` и свой рой.
4. **Решение:** по реальным ток/с и загрузке посчитать месячный бюджет ([docs/06-ekonomika.md](docs/06-ekonomika.md))
   и выбрать: аренда по часам, аренда с обязательством или покупка.

## Скрипты

| Файл | Что делает |
|---|---|
| `scripts/serve_vllm.sh` | запуск vLLM с готовыми профилями: `h200`, `b200`, `2xh100`, `2xpro6000`, `pro6000`, `h100`, `2x5090`, `5090` |
| `scripts/vram_calc.py` | калькулятор: влезет ли, сколько агентов, какая скорость и цена (откалиброван по реальным замерам) |
| `scripts/bench_swarm.py` | нагрузочный тест роя: TTFT, ток/с, доля кэша, приёмка MTP, вытеснения |
| `scripts/swarm_demo.py` | пример роя: планировщик → N агентов → сборщик (режимы `shared` и `map`) |
| `scripts/mock_server.py` | мок OpenAI-совместимого сервера для проверки всего без GPU |

```bash
pip install -r requirements.txt
python3 scripts/vram_calc.py --compare                      # сравнить конфигурации
python3 scripts/vram_calc.py --gpu h200 --agents 10 --context 262144
```

## Честно о точности

- Характеристики модели, флаги и поведение vLLM/SGLang сверены с исходным кодом и официальными рецептами
  (vLLM 0.30.0, SGLang 0.5.20).
- Скорости — расчёт, откалиброванный по публичным замерам на RTX PRO 6000, RTX 5090, H100, H200 и DGX Spark
  (±25%). Для B200 публичных замеров нет. Ничего из этого не запускалось на GPU в рамках этой работы —
  первый же прогон `bench_swarm.py` на арендованной машине даст точные цифры.
- Цены собраны из открытых источников (каталоги облаков, агрегаторы цен, прайсы API) на 25.09.2026.
